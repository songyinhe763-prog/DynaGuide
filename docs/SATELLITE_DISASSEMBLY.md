# 自由漂浮卫星拆解基准（`core/satellite`）

大创课题背景：失效卫星的在轨拆解/回收。服务星（SC-1 概念：攀爬+操作臂）与被服务目标
**同处自由漂浮状态**，因此任何用来拆下部件的接触力都会被基座反作用——"拆下来了但把卫星
推转了"在轨就是失败。本基准把这个约束做进了仿真与评测。

## 1. 场景

`make_sc1_spec()`（`core/satellite/spec.py`）：

| 部件 | 质量 | 连接方式 | 拆解协议 |
|---|---|---|---|
| `payload_box` | 3.2 kg | **螺栓**（轴向 +x，需转 90°） | 先拧 90°，再轴向拉 > 4 N 的破断力 |
| `solar_panel` | 1.4 kg | **卡扣**（轴向 −x） | 先压入 6 mm，再拉 > 2 N |
| `battery_module` | 2.6 kg | **摩擦销**（轴向 −y） | 直接拉 > 7 N |

基座 28.27 kg、惯量 (0.62, 0.58, 0.41) kg·m²（与 SC-1 方案一致）。
动作空间 7 维：`a[0:3]` 基座系平动意图（×0.02 m），`a[3:6]` 转动意图（×0.2 rad），`a[6]` 夹爪（>0 夹紧）。

## 2. 微观重力物理

`SatelliteEnv.step()` 是准静态阻抗模型：

1. 动作解释为期望位移 `dp`，转成阻抗力 `F = k_imp · |dp_blocked|`（`k_imp = 900 N/m`）；
2. **被阻挡的那一部分位移**才产生接触力（例如螺栓没拧就拉、或拉的角度有偏）；
3. 该力作为**反作用力偶**加到自由漂浮基座：`ω += (r × −F)·dt / I`，姿态按四元数积分；
4. 安全预算分两档：
   - **硬中止** `force_limit = 8 N`（超过即判定回合失败，模拟硬件保护）；
   - **运行预算** `force_budget = 4 N`：`constraint_satisfied` 指标用它打分；
   - 姿态预算 `attitude_budget = 0.12 rad`，回合上限 `horizon = 120` 步；
   - 螺栓/卡扣的到位容差 `twist_tol = 0.22 rad`（螺纹间隙）。

可见"正确协议 + 纯轴向拉"几乎不产生反作用，而"先拽再拧"或"斜着拉"会立刻把基座推转。

## 3. 三种示范策略（多模态来源）

`ScriptedExpert(behavior=...)`：

- `safe`：正规协议（拧/压→轴向拉），基座漂移 ~0.09 rad、接触力 ~1.5 N；
- `impatient`：先拽 4 步再拧，漂移 ~0.21 rad、接触力 ~3.9 N（机械上多数仍能拆下）；
- `offset`：沿倾斜 0.25 rad 的方向抽出，漂移 ~0.35 rad、成功率降到 ~47%。

混合采集（默认 60/20/20）后做行为克隆，基础策略学到的是三种策略的**平均**——正是 DynaGuide
要解决的推理期行为选择问题。

## 4. 观测与潜空间

本体感知（36 维，`proprio_dim(3)`）：基座位姿/速度(13) + 末端位姿(6) + 夹爪(1) + 每个模块
`[attached, twist_ratio, press_ratio, pull_ratio, grasp_dist]`(5×3) + 时间(1)。

动力学的"潜空间"用**冻结的语义编码器** `SemanticLatentEncoder`（22 维：姿态、角速度、末端位置、
夹爪 + 每模块 4 个进度量），按**固定名义尺度**标准化（1 单位 = 1 个任务容差），
避免二值特征（`attached`）在经验标准差下把潜空间尺度炸掉。
引导条件 `g⁺/g⁻` 就是**安全/不安全回合的末端状态**在同一潜空间中的嵌入。

## 5. 评测口径（四维）

```text
success                 : 目标模块被拆下（回合在拆下瞬间结束；多目标时继续下一个模块）
constraint_satisfied    : success 且 基座漂移 ≤ 0.12 rad 且 接触力 ≤ 4 N（运行预算）
base_drift / max_force  : 回合内最坏值
```

第三维不能省：在轨任务里"成功但把卫星推飞"必须计入失败。
示范数据本身的 `constraint` 比率：`safe` ≈ 97%、`impatient` ≈ 8%（先拽后拧把基座推过 0.12 rad）、
`offset` ≈ 4%（斜拉产生切向力矩）——这就是正/负引导条件的来源。

> 若要把"搬回收纳位姿"也计入任务，设 `SatelliteSpec.require_stow = True`：此时必须到达
> `capture_pos`（`capture_tol = 3 cm`）才判定完成。

## 6. 与真实卫星仿真的衔接

本基准刻意做成**零依赖（numpy）**，用于把算法跑通、把"反作用力矩"这一物理约束显式建模并
可微化给引导用（`DifferentiableDisassemblyModel`）。要做更高保真的验证，可换到 MuJoCo 系
自由漂浮仿真（如 mjorbit 这类带轨道动力学/接触的 MuJoCo 环境，或自建 MJCF 场景），
把 `SatelliteEnv` 的接口（`reset/step/is_success/proprio`）替换即可，引导侧代码不需要改。
